## 项目愿景

一个终端原生的多模型 AI 编程助手。用户可以同时与多个大模型对话，并排对比它们的回答；执行任务时，以结构化提案的形式审查每个模型的方案，选择最佳结果。

**与 Claude Code 的核心差异：** 不绑定单一供应商。每轮对话同时跑 N 个模型，把"事先选模型"变成"事后比结果"。

## 展示模式（混合模式）

### 对话模式 — 群聊式交互（类比工作群）

终端始终展示所有模型的多栏面板，像一个群聊。用户通过 `@` 控制消息路由，无需模式切换。

#### 消息路由

```
用户输入                            谁收到
─────────────────────────────────────────────
这个函数怎么优化？         →    所有模型（广播）

@claude 你这个方案展开讲讲   →    只有 Claude

@claude @gpt 你们比比         →    Claude + GPT
```

- 不加 `@` → 广播给所有人，消息追加到所有模型历史
- `@模型名` → 只发给指定模型，消息只追加到该模型历史
- `@` 支持简写：`@c` = Claude，`@g` = GPT，`@ds` = DeepSeek
- 收到消息的模型面板边框高亮，未收到的面板保持可见但置灰（用户能看到消息流过但不参与）

#### @ 智能联想

输入 `@` 时触发模型列表下拉，类似 Claude Code 输入 `/` 联想命令：

```
┌──────────────────────────────────────┐
│ @Claude (Opus)        [c]           │  ← 当前高亮项
│ @GPT-4o               [g]           │
│ @DeepSeek-V3          [ds]          │
│ @Gemini-2.5           [gm]          │
│ @all                  [广播]         │
└──────────────────────────────────────┘
  ↑↓ 选择  Enter 确认  Tab 补全  / 可继续输入模糊匹配
```

- `@` 弹出所有已配置模型 + `@all`（广播）
- 继续输入字符做模糊匹配：`@cl` → 只显示 Claude
- `↑↓` 方向键选择，`Enter` 确认选中
- `Tab` 补全当前高亮项，光标后继续输入
- 选中一个后可继续输入 `@` 添加第二个模型
- `Esc` 关闭下拉

#### 全屏聚焦（可选，按需使用）

跟某个模型需要深度长聊时，`Ctrl+1/2/3` 将对应模型面板全屏展开，输入框默认只发给该模型（不需要 `@` 前缀）。`Esc` 退回多面板。

#### 交互总览

| 操作 | 效果 |
|------|------|
| 直接输入 | 广播给所有模型 |
| `@claude 消息` | 只发给 Claude |
| `@claude @gpt 消息` | 发给 Claude 和 GPT |
| `Ctrl+1/2/3` | 对应模型全屏聚焦 |
| `Esc` | 退出全屏 |
| `d` | 对比两个模型的输出（Diff 视图） |
| `r` | 重置模型上下文到公共基线 |

#### 对话历史策略

每个模型维护**独立的对话历史**。广播消息同时追加到所有历史，`@` 定向消息只追加到被 @的模型。全屏聚焦时的对话也只追加到焦点模型。这带来一个自然的动态：
- 你可以先广播"这个 Bug 怎么看"，看大家答案各异
- 然后 `@claude` 追问"你那个方案详细说"，只有 Claude 知道你在追问什么
- 再广播"继续完善"，所有人继续，但 Claude 带着之前的追问上下文

### 任务模式 — 结构化提案对比

当模型需要修改文件或执行命令时，界面切换为提案视图：

- 每个文件、每个模型并排展示 Diff
- 按提案粒度逐条接受/拒绝（不是要么全接受要么全拒绝）
- 多个模型修改同一行代码时自动标记冲突

## 架构（四层）

```
UI 层（Ink/React）
    ↕
Core 层（会话管理 → 流调度 → 任务引擎）
    ↕
Provider 层（统一接口 → 各适配器）
    ↕
工具运行时（读文件、写文件、编辑、Grep、Glob、Bash、Git…）
```

| 层 | 职责 |
|----|------|
| UI | 只管渲染，不碰模型逻辑 |
| Core | 多模型编排、对话状态管理、任务提案处理 |
| Provider | 把不同 LLM API 归一到同一接口，对上层透明 |
| 工具 | 文件/Shell 操作，带权限控制 |

## 文件隔离：Git Worktree

每个模型分配独立的 worktree。不共享文件系统 — 无冲突、无锁、干净的 Diff。

```
用户项目：~/project（main 分支）

用户提问后：
  → git worktree add /tmp/agent-claude   -b agent/claude-{任务ID}
  → git worktree add /tmp/agent-gpt4     -b agent/gpt4-{任务ID}
  → git worktree add /tmp/agent-deepseek -b agent/deepseek-{任务ID}

每个模型在隔离环境中工作。
用户选定优胜方案 → 合并对应 worktree，丢弃其余。
```

**理由：** 让多个 Agent 共享文件系统会引入复杂的冲突检测、文件锁和合并逻辑，复杂度和价值不成比例。Worktree 隔离让每个 Agent 的输出是干净的 Git Diff，零交叉污染。
