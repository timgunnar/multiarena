---

## 项目愿景

一个终端原生的多模型 AI 编程助手。用户可以同时与多个大模型对话，并排对比它们的回答；执行任务时，以结构化提案的形式审查每个模型的方案，选择最佳结果。

**与 Claude Code 的核心差异：** 不绑定单一供应商。每轮对话同时跑 N 个模型，把"事先选模型"变成"事后比结果"。

## 展示模式（混合模式）

### 对话模式 — Tab 驱动交互

#### 三区固定布局

终端分为三个区域，顶部状态条和底部输入栏始终固定，仅中间输出区域可滚动：

```
┌─ Claude ───────┬── GPT-4o ● ───┬── DeepSeek ● ──────────┐  ← 固定，始终可见
├──────────────────────────────────────────────────────────┤
│                                                          │
│  输出区域（可滚动）                                        │
│  · 当前对话模型的完整回复，全宽展示                          │
│  · 鼠标滚轮 / ↑↓ 翻看历史                                  │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ [Claude] › 这个方案展开讲讲                                 │  ← 固定，始终可见
└──────────────────────────────────────────────────────────┘
```

- **顶部状态条** — 显示所有模型名称 + 新内容指示（●），一行高
- **中间输出区** — 唯一可滚动区域，当前模型的全宽详情
- **底部输入栏** — 前缀标识对话目标，始终可见

#### Tab 切换对话目标

`Tab` 是唯一的切换方式，循环切换目标模型。切换时无动画、无闪烁，仅做两件事：

**1. 输入栏前缀切换**

```
[全部] ›            ← 默认，广播给所有模型
  ↓ Tab
[Claude] ›          ← 消息只发给 Claude
  ↓ Tab
[GPT-4o] ›          ← 消息只发给 GPT-4o
  ↓ Tab
[全部] ›            ← 循环回到广播
```

**2. 输出区域联动切换**

当前对话的模型在输出区域全宽展开详情，其余模型显示在顶部固定状态条（始终可见，不随输出滚动）：

```
┌─ Claude ● ───┬── GPT-4o ───┬── DeepSeek ● ──────────┐  ← 状态条
├──────────────────────────────────────────────────────┤
│                                                      │
│  Claude 的完整回复                                    │
│  全宽展示，代码块完整可读                               │
│  鼠标滚轮 / ↑↓ 翻看历史对话                            │
│                                                      │
├──────────────────────────────────────────────────────┤
│ [Claude] ›                                            │  ← 底部常驻输入栏
└──────────────────────────────────────────────────────┘
```

`Tab` 切到 GPT-4o：
```
┌─ Claude ───────┬── GPT-4o ● ───┬── DeepSeek ● ──────────┐
├──────────────────────────────────────────────────────────┤
│                                                          │
│  GPT-4o 的完整回复                                        │
│  全宽展示                                                 │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ [GPT-4o] ›                                               │
└──────────────────────────────────────────────────────────┘
```

#### 广播模式

目标为「全部」时，消息广播给所有模型，所有模型后台并发流式产出。输出区域显示摘要面板（水平均分 N 栏，每栏 4-5 行），用户可按 `Tab` 切到任意模型查看完整输出。

```
[全部] › 这个函数怎么优化？    → 所有模型收到，所有模型回复
```

#### 并排对比

按 `d` 进入对比模式，将当前模型与另一个模型并排各半宽展示，用于逐行对比代码或方案差异。

#### 交互汇总

| 操作 | 效果 |
|------|------|
| `Tab` | 循环切换对话目标（全部 → Claude → GPT → DeepSeek → 全部） |
| `输入 + Enter` | 发送给当前前缀指示的目标 |
| `Ctrl+1/2/3/4…` | 快速跳到指定模型（等价于多次 Tab） |
| `Ctrl+0` | 切回「全部」 |
| `d` | 当前模型与另一个并排对比 |
| `Ctrl+M` | 静音/取消静音当前模型 |
| `r` | 重置当前模型上下文 |
| 鼠标滚轮 / `↑↓` | 在输出区域滚动翻看历史 |

#### 交互增强

**差异检测（代码 & 工具调用限定）**

仅对代码块和工具调用做自动差异标记，不对自然语言做语义判定：

| 检测对象 | 方式 | 示例 |
|----------|------|------|
| 代码块 | AST / 文本级 Diff | Claude 和 GPT 改了同一个函数但逻辑不同 |
| 工具调用 | 结构化对比（文件、行范围、命令） | 两个模型想改同一个文件的同一段代码 |
| 选项型输出 | 字符串匹配 | 两模型对"选 A/B/C"给出不同答案 |

纯文本回答不做自动判定，用户手动按 `d` 触发对比。底部提示行：

```
⚠ 分歧: src/auth.ts (2个方案) · 设计模式选择 (3个观点不同)
```

**静音开关**

每个模型面板右上角 `●` 指示灯：
- `Ctrl+M` — 切换当前焦点模型的静音状态
- 静音后：面板折叠为一行最小化显示，下次广播不发送消息给该模型
- 再次 `Ctrl+M` 解静，恢复上下文继续参与

**上下文水位线**

每个面板顶部细线显示该模型的上下文使用率：

```
Claude ████████░░ 80%  ·  GPT ████░░░░░░ 40%  ·  DeepSeek ██████████ 98% ⚠
```

接近上限时变黄/变红，提醒用户及时管理上下文。

#### 对话历史策略

每个模型维护**独立的对话历史**。广播消息同时追加到所有历史，`@` 定向消息只追加到被 @的模型。全屏聚焦时的对话也只追加到焦点模型。这带来一个自然的动态：
- 你可以先广播"这个 Bug 怎么看"，看大家答案各异
- 然后 `@claude` 追问"你那个方案详细说"，只有 Claude 知道你在追问什么
- 再广播"继续完善"，所有人继续，但 Claude 带着之前的追问上下文

### 任务模式 — 结构化提案对比

当模型需要修改文件或执行命令时，界面切换为提案视图：

- 每个文件、每个模型并排展示 Diff
- 按提案粒度逐条接受/拒绝（不是要么全接受要么全拒绝）
- 多个模型修改同一行代码时自动标记冲突

## 架构（四层）

```
UI 层（Ink/React）
    ↕
Core 层（会话管理 → 流调度 → 任务引擎）
    ↕
Provider 层（统一接口 → 各适配器）
    ↕
工具运行时（读文件、写文件、编辑、Grep、Glob、Bash、Git…）
```

| 层 | 职责 |
|----|------|
| UI | 只管渲染，不碰模型逻辑 |
| Core | 多模型编排、对话状态管理、任务提案处理 |
| Provider | 把不同 LLM API 归一到同一接口，对上层透明 |
| 工具 | 文件/Shell 操作，带权限控制 |

## 文件隔离：Git Worktree

每个模型分配独立的 worktree。不共享文件系统 — 无冲突、无锁、干净的 Diff。

```
用户项目：~/project（main 分支）

用户提问后：
  → git worktree add /tmp/agent-claude   -b agent/claude-{任务ID}
  → git worktree add /tmp/agent-gpt4     -b agent/gpt4-{任务ID}
  → git worktree add /tmp/agent-deepseek -b agent/deepseek-{任务ID}

每个模型在隔离环境中工作。
用户选定优胜方案 → 合并对应 worktree，丢弃其余。
```

**理由：** 让多个 Agent 共享文件系统会引入复杂的冲突检测、文件锁和合并逻辑，复杂度和价值不成比例。Worktree 隔离让每个 Agent 的输出是干净的 Git Diff，零交叉污染。
